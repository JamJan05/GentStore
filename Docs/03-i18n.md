# 03 — Bilingualism (Polish / English)

Gentstore speaks two languages: **Polish** and **English**. This is not a feature bolted on at
the end — the rules below have applied since the first line of code.

## 1. Choosing the mechanism

We use **Qt's native system**: `QTranslator` plus `.ts` files (XML) compiled to `.qm`.

Why not `gettext`: PyQt6 gets translation support for free (`self.tr()`, the context being the
class name, plurals through `%n`), the `pylupdate6`/`lrelease` tools ship in the same package as
everything else, and Qt Linguist is a comfortable editor. Mixing two systems would only do harm.

## 2. The rule: the sources are in English

**There are no Polish strings in the source code.** Every user-visible string is written in
English and wrapped in `tr()`; Polish comes into being as a translation in `gentstore_pl.ts`.

```python
# right
self.install_button.setText(self.tr("Install"))
self.hint.setText(self.tr("Nothing has been removed yet."))

# wrong — Polish in the code
self.install_button.setText("Zainstaluj")

# wrong — no tr()
self.install_button.setText("Install")
```

The mock-up is in Polish, so its wording is treated as a **ready-made `pl` translation**, not as
a source. For each screen we record in the `.ts` a pair “English msgid → the Polish from the
mock-up”, so that none of the careful, natural phrasing of the original descriptions is lost.

## 3. What we do **not** translate

Deliberately left alone, because these are the things the user will retype into a terminal or
look up in the Gentoo documentation:

- package names and atoms (`media-video/mpv`, `>=media-libs/libplacebo-7.349.0`);
- commands and their options (`emerge -pvuDN --changed-use @world`);
- paths (`/etc/portage/package.use/mpv`);
- the names of Portage variables and keywords (`ACCEPT_KEYWORDS`, `REQUIRED_USE`, `IUSE`,
  `~amd64`, `@world`);
- USE flag names and repository identifiers (`vulkan`, `::guru`);
- raw command output, elog text, news text, licence texts.

A separate case: **USE flag descriptions**. They come from `use.desc`, `use.local.desc` and
`metadata.xml` — that is, from the Portage tree — and they are in English there. We leave them
as they are rather than machine-translating them. What we do translate is **our own** labels
around them (“Pulls in”, “Without this flag”, “What does this flag change?”) and the sentences
we generate from the data ourselves (e.g. “without this flag mpv uses OpenGL only” — the
template is ours, so it goes through `tr()`).

## 4. Files and workflow

```
gentstore/i18n/
├── gentstore_pl.ts    # the Polish translation — maintained by hand
├── gentstore_en.ts    # a 1:1 pass-through, kept so the switch has two real positions
├── gentstore_pl.qm    # generated, not committed
└── gentstore_en.qm    # generated, not committed
```

Updating the translations after adding new `tr()` calls:

```bash
# 1. extract the new strings from the sources
pylupdate6 gentstore/**/*.py -ts gentstore/i18n/gentstore_pl.ts gentstore/i18n/gentstore_en.ts

# 2. translate (Qt Linguist, or by hand in the XML)
linguist gentstore/i18n/gentstore_pl.ts

# 3. compile
lrelease gentstore/i18n/gentstore_pl.ts gentstore/i18n/gentstore_en.ts
```

In practice `tools/i18n.py` wraps all three steps (`update` / `compile` / `all`), because on
Gentoo `pylupdate6` and `lrelease` are not always in `PATH`.

Step 3 is also wired into the build (`pyproject.toml`), so that the `.qm` files come into being
at install time, and `.gitignore` excludes `*.qm`. Only the `.ts` files are kept in the
repository.

### Trap: `lupdate` reads the source as text

`lupdate` does not run the code — it **parses** it. Everything it is meant to find must
therefore be a literal at the call site:

```python
QT_TRANSLATE_NOOP(CONTEXT, "Search & install")   # WRONG — lupdate cannot see this
QT_TRANSLATE_NOOP("Pages", "Search & install")   # RIGHT
```

The version on the left cost us the whole set of screen names in S3. The failure is silent and
particularly treacherous: `lupdate` reports no error, it just marks the old entries as
`type="vanished"`, `lrelease` skips them, and the sidebar in the window suddenly speaks English
while the rest of the interface is in Polish. Hence `tests/test_i18n.py` — it checks that
**no** entry in the `.ts` carries a `type` attribute and that every title from `PAGES` is in the
catalogue.

### Trap: `tr()` only through `self`

`tr()` is a `QObject` method, and its context is the class **the call sits in**. The extractor
reads the source as text and recognises `self.tr(…)` — and nothing else:

```python
QMessageBox.warning(window, window.tr("Running as root"), …)   # WRONG — falls out of the catalogue
QMessageBox.warning(self, self.tr("Running as root"), …)       # RIGHT
```

The version on the left **compiles, works and quietly returns the English original for ever**.
It happened in S4 with the “running as root” warning, written in `app.py` rather than in the
window. The fix: move the text into the class that shows it. The safeguard:
`tests/test_i18n.py` walks the AST of every file and catches `anything.tr("…")` where “anything”
is not `self`.

### Trap: `%n` does not make a plural on its own

Whether a message is a plural form is decided by the extractor from the **shape of the call in
the source**, not from the fact that the text contains `%n`:

```python
self.tr("%n new", "", count)                    # RIGHT — numerus="yes"
{Action.NEW: self.tr("%n new", "", count)}[a]   # WRONG — the same call inside a dict
```

The second version lands in the catalogue as **an ordinary string with a single form**. In
Polish that means one ending instead of three, which is the correct result for one third of the
values. It happened in S8, in the summary of the update preview.

Worse: **turning the call into a numerus form is not enough.** `pylupdate6` merges with the
existing catalogue and does not change an entry that is already there — the old, non-numerus
entry survives. It has to be deleted from the `.ts` first, and only then can `update` be run.

The safeguard: `tests/test_i18n.py` checks that every message containing `%n` has
`<numerusform>` forms.

### Trap: two extractors mean two incompatible catalogues

`pylupdate6` (from `dev-python/pyqt6`) and `lupdate` (from `dev-qt/qttools`) differ in the
details — most visibly in that `lupdate` treats `#:` comments as notes for the translator and
`pylupdate6` does not. A catalogue written by one and refreshed by the other gets **every
message twice**: the old one marked `vanished`, and a fresh `unfinished` one beside it.

This happened on exactly the day `dev-python/pyqt6` appeared on the system and `pylupdate6`
jumped into `PATH` in the middle of the project. That is why `tools/i18n.py` has a **pinned**
extractor (`EXTRACTOR = "pylupdate6"`) and deliberately has no fallback, and why
`tests/test_i18n.py` checks that no context holds two entries with the same source.

## 5. Choosing the language at runtime

The order of resolution at startup:

1. the `--lang pl|en` CLI switch (useful for tests and screenshots);
2. the setting saved in `QSettings` (the `ui/language` key);
3. `QLocale.system()` — `pl_PL` → Polish, anything else → English.

Changing the language in Settings works **without a restart**: `app.py` exposes
`retranslate()`, every page implements `changeEvent()` with `LanguageChange` handling and
rebuilds its strings. That requires strings to be set in a `retranslate_ui()` method rather than
once in `__init__` — a rule enforced since S1, because gluing it onto finished screens later is
painful.

## 6. Plurals and formatting

Polish has three plural forms (1 pakiet / 2 pakiety / 5 pakietów). Qt handles that, as long as
we use `%n`:

```python
label.setText(self.tr("%n package(s) to update", "", count))
```

Three `<numerusform>` variants are then created in the `.ts`. Concatenation of the
`str(n) + tr(" packages")` kind is forbidden — Polish cannot be inflected correctly that way.

Numbers, sizes and dates are formatted through `QLocale`, not by hand — the mock-up shows
`3 214 KiB` with a space as the thousands separator, which is the Polish convention; in English
it has to come out as `3,214 KiB`.

## 7. Quality control

Active since S3 (`tests/test_i18n.py`):

- no entry in the `.ts` has a `type` attribute (`unfinished`, `vanished`, `obsolete`);
- no entry is empty;
- no context holds two entries with the same source;
- every screen title from `PAGES` is present in the `Pages` context;
- every `%n` entry in the Polish version has exactly three `<numerusform>` forms;
- (since S4) no file calls `tr()` on somebody else's object — checked through the AST;
- (since S8) every message with `%n` has plural forms.

To be added in S12:

- no Polish characters (`ąćęłńóśźż`) in `.py` files outside comments;
- no string literals reaching `setText`/`setToolTip`/`setWindowTitle` without `tr()`.
